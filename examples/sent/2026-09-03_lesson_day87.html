Day 87: Agent Skills (Anthropic) – SKILL.md, Progressive Disclosure vs MCP
TL;DR
Learn how Anthropic's SKILL.md defines reusable agent capabilities, how progressive disclosure reveals them safely, and how this differs from the Modular Conversational Prompt (MCP) approach.

In plain English

Anthropic lets you describe an agent's abilities in a markdown file called SKILL.md. Each skill lists a name, description, required inputs, and a short code snippet that the runtime can execute. When a user asks the agent to perform a task, the system can either expose the full skill definition immediately (eager disclosure) or reveal only what is needed step‑by‑step (progressive disclosure). Progressive disclosure reduces the attack surface because the model only sees the minimal context required to solve the current sub‑task.
MCP, on the other hand, bundles many skills into a single large prompt that the model parses each turn. While MCP can be simpler to ship, it makes debugging harder, inflates token usage, and mixes concerns that would otherwise be isolated in separate skill modules. By keeping skills modular and disclosed progressively, you gain better observability, easier fine‑tuning of individual components, and clearer production boundaries.

Think of it this way

Think of a restaurant kitchen: SKILL.md is the recipe book where each dish (skill) is written on its own card. Progressive disclosure is like handing the chef only the card for the dish they’re currently cooking, instead of laying out the entire book on the counter (MCP), which can cause confusion and waste space.

In code

from anthropic import Anthropic

def register_skill(name, description, fn):
    return {"name": name, "description": description, "run": fn}

# Example skill: add two numbers
add_skill = register_skill(
    "add_numbers",
    "Adds two integers and returns the sum.",
    lambda a, b: a + b,
)

# Progressive disclosure: only send skill metadata when needed
client = Anthropic()
response = client.messages.create(
    model="claude-3-sonnet-20240229",
    max_tokens=256,
    messages=[
        {"role": "user", "content": "What is 7 plus 5?"},
        {"role": "assistant", "content": "Sure, I can use the add_numbers skill.", "tool_calls": [{"name": "add_numbers", "input": {"a": 7, "b": 5}}]},
    ],
    tools=[add_skill],
)
print(response.content)
The snippet registers a simple add_numbers skill and shows how the model can call it with only the necessary metadata, illustrating progressive disclosure.

Why it matters for AI Eng interviews

Employers look for engineers who can build agents that integrate RAG pipelines, support dynamic tool calling, and stay observable in production; using SKILL.md with progressive disclosure gives fine‑grained control, lower token costs, and easier evaluation (evals) compared to monolithic MCP prompts, directly aligning with job‑descriptions that emphasize modularity, fine‑tuning, and production‑ready observability.
One thing to remember
Expose only the skill details the model needs at the moment—keep the rest hidden for safety and efficiency.
