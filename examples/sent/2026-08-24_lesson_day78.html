Day 78: Prompt Caching
TL;DR
Prompt caching lets you reuse the model’s computed representation of a static prompt prefix, cutting inference cost by up to 90%.

In plain English

When a language model processes a prompt, it first turns the text into vectors (embeddings) and runs several transformer layers over them. This "prefix" work is repeated every time you send the same introductory text, even if only the trailing user query changes, wasting compute and money.
Anthropic’s prompt‑caching feature lets you store the intermediate representation of that static prefix once and attach a cache identifier to later calls. The model skips the expensive forward pass for the cached part and only computes the new suffix, giving you roughly a ten‑fold reduction in token‑price for long, reusable prompts.

Think of it this way

Think of making a big batch of soup base at the start of the week: you simmer the vegetables and spices once, then each night you just add fresh ingredients for that day's meal instead of re‑cooking the whole pot every time.

In code

import os
from anthropic import Anthropic

client = Anthropic(api_key=os.getenv("ANTHROPIC_API_KEY"))

# First call stores the prefix in the cache
response1 = client.completions.create(
    model="claude-2.1",
    max_tokens=5,
    prompt="You are a helpful AI assistant. Answer concisely.\n\nUser: How does prompt caching work?\nAssistant:",
    cache_control={"type": "cached"},
)

# Subsequent call reuses the cached prefix (identified by its hash)
response2 = client.completions.create(
    model="claude-2.1",
    max_tokens=5,
    prompt="You are a helpful AI assistant. Answer concisely.\n\nUser: What are the benefits?\nAssistant:",
    cache_control={"type": "cached", "cache_id": response1.cache_id},
)
The first request caches the shared prompt prefix; the second request references the same cache_id so the model only processes the new question.

Why it matters for AI Eng interviews

Employers look for engineers who can shrink RAG pipelines, build cost‑effective agents, and keep production LLM services observable and scalable. Prompt caching directly reduces inference spend, simplifies monitoring (fewer repeated token logs), and fits into fine‑tuning or MCP workflows where the same system prompt is reused thousands of times.
One thing to remember
Cache the immutable part of your prompt once, and reuse its cache_id for every new user query to slash latency and cost.
