Day 75: Observability for LLMs with OpenTelemetry
TL;DR
Learn how to instrument large language model pipelines with OpenTelemetry to capture traces, spans, and metrics that keep production systems reliable and debuggable.

In plain English

Observability is the practice of making a system’s internal state visible from the outside. In the context of LLMs, you want to know when a request enters your service, how long the model inference takes, whether a retrieval‑augmented generation (RAG) step succeeded, and what resource usage each component incurred. OpenTelemetry (OTel) provides a vendor‑neutral API to emit traces (ordered events), spans (individual timed operations), and metrics (numeric measurements) that can be collected by any backend such as Jaeger, Prometheus, or a cloud observability platform.
To instrument an LLM pipeline, wrap each logical piece—API gateway, prompt construction, vector search, model inference, post‑processing—in a span. Add attributes like model name, token count, and request ID so you can filter later. Emit counters for requests, histograms for latency, and gauges for GPU memory. This structured data lets you detect slowdowns, model drift, or failures in downstream services before they affect users.
Because LLM workloads are often asynchronous and batch‑oriented, make sure to propagate the trace context across threads, async calls, and external services (e.g., a vector DB). Doing so stitches together a complete end‑to‑end picture, which is essential for debugging production AI features such as agents that call multiple tools or fine‑tuning jobs that run in the background.

Think of it this way

Think of tracing an LLM request like following a pizza order from the phone call to the oven to the delivery driver. Each step—taking the order, preparing the dough, adding toppings, baking, and delivering—gets a timestamp and notes (span). If the pizza is late, you can look at the timestamps to see whether the oven was the bottleneck or the driver got stuck in traffic.

In code

import time
from opentelemetry import trace, metrics
from opentelemetry.sdk.resources import Resource
from opentelemetry.sdk.trace import TracerProvider
from opentelemetry.sdk.metrics import MeterProvider
from opentelemetry.sdk.trace.export import BatchSpanProcessor, ConsoleSpanExporter
from opentelemetry.sdk.metrics.export import ConsoleMetricExporter, PeriodicExportingMetricReader

# Setup tracer and meter
trace.set_tracer_provider(TracerProvider(resource=Resource.create({"service.name": "llm-service"})))
tracer = trace.get_tracer(__name__)
trace.get_tracer_provider().add_span_processor(BatchSpanProcessor(ConsoleSpanExporter()))
metrics.set_meter_provider(MeterProvider(metric_readers=[PeriodicExportingMetricReader(ConsoleMetricExporter())]))
meter = metrics.get_meter(__name__)
latency_hist = meter.create_histogram("llm_inference_latency_ms")

def infer(prompt: str) -> str:
    with tracer.start_as_current_span("model_inference") as span:
        span.set_attribute("model.name", "gpt-4")
        span.set_attribute("prompt.length", len(prompt))
        start = time.time()
        # Simulated model call
        time.sleep(0.12)
        result = "generated text"
        latency = (time.time() - start) * 1000
        latency_hist.record(latency, {"model.name": "gpt-4"})
        return result
The snippet creates an OpenTelemetry tracer and meter, wraps a fake model call in a span, records model name and prompt length as attributes, and logs inference latency to a histogram.

Why it matters for AI Eng interviews

Production AI jobs demand observability to meet SLAs for RAG pipelines, multi‑tool agents, and continuous fine‑tuning; metrics and traces let you spot latency spikes, token‑budget overruns, or downstream service failures, while standardized OpenTelemetry data feeds into monitoring dashboards, alerting, and root‑cause analysis required by most AI engineering JD listings.
One thing to remember
Instrument every logical step of your LLM workflow with spans and export the data via OpenTelemetry for reliable production monitoring.
