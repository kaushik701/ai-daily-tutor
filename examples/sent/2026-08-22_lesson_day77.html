Day 77: Cost and Latency Optimization
TL;DR
Learn how model routing, caching, batching, and streaming cut cloud spend and response time in production AI services.

In plain English

In a production system you often have many different model versions (small fast models for simple queries, larger ones for complex tasks). Model routing decides which version to invoke based on request characteristics, so you avoid paying for a heavyweight model when a lightweight one will do.\n\nCaching stores recent inference results—like embeddings or generated text—so repeated calls return instantly without hitting the model again. Batching groups independent requests into a single API call, letting the accelerator process them in parallel and amortizing overhead. Streaming splits a large response into chunks, letting the client start consuming data while the model continues generating, which reduces perceived latency.

Think of it this way

Think of a restaurant kitchen: the chef routes simple orders to a fast grill, caches pre‑made sauces for repeat dishes, batches multiple salads into one prep station, and plates a soup as it simmers so diners can start sipping before the whole pot is ready.

In code

import time, asyncio\ncache = {}\nasync def get_embedding(text):\n    if text in cache:\n        return cache[text]\n    # simulate expensive model call\n    await asyncio.sleep(0.1)\n    embed = hash(text) % 1000\n    cache[text] = embed\n    return embed\n\nasync def batch(texts):\n    return await asyncio.gather(*(get_embedding(t) for t in texts))\n\n# example\ntexts = [\"hello\",\"world\",\"hello\"]\nembeds = asyncio.run(batch(texts))\nprint(embeds)
The snippet caches embeddings and batches multiple requests, so repeated inputs hit the cache and the batch runs all uncached calls concurrently, reducing latency and cost.

Why it matters for AI Eng interviews

Senior AI engineers must keep RAG pipelines responsive, agents cheap, and evaluation suites fast; each extra millisecond multiplies cloud spend. Fine‑tuning services repeatedly invoke the same base model, so routing, caching, and batching directly lower GPU hours. Observability dashboards rely on stable latency metrics, and the Model Control Plane (MCP) needs predictable routing policies to meet SLAs in production environments.
One thing to remember
Cache what you can, batch what you can, and route wisely to keep cost low and latency low.
